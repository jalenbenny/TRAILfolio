Abstract

This is the Lakefront AI Ramblers entry to the MEDIQA-SYNUR 2026 shared task: extracting structured nursing observations from synthetic nurse-patient transcripts against a fixed schema of 193 observation types. The system combines lexical (BM25) and dense (BGE) retrieval to narrow the schema per transcript segment. An open-source LLM then extracts the observations, and a separate LLM verification stage filters out hallucinated ones. It was built and evaluated on synthetic nursing transcripts, but it should generalize to other clinical transcripts given a curated schema. The work is published in the ClinicalNLP workshop proceedings at LREC 2026.

Methods Summary

The pipeline has five stages, each a script in src/ and run through src/main.py:

  1. Segmentation. Split each transcript into segments, either rule-based or LLM-based.
  2. Schema RAG. Retrieve the top 60 of the 193 schema rows per segment using a hybrid of BAAI/bge-base-en-v1.5 and BM25 (α = 0.6).
  3. Extraction. An LLM fills in values for the retrieved schema rows. Models tried: GPT-4o / GPT-4o-mini, and Llama-3-8B and Llama-3.3-70B, both base and LoRA-fine-tuned (SFT) on train or train+dev, with 4-bit quantization for 70B.
  4. Self-consistency voting. Majority or union vote over 3 sampled runs (T = 0.3).
  5. Verification. A second LLM pass (Llama-3.3-70B or GPT-4o-mini) drops observations that the transcript doesn’t support.

Scoring uses the organizers’ official evaluation script (src/mediqa_synur_eval_script.py). The 70B work ran on the Valkyrie GPU cluster under SLURM (valkyrie_scripts/). Setup and run steps are in docs/setup.md.

Key Results

Development-set results (101 transcripts) from results/outputs/comparison_results.csv:

Configuration P R F1
GPT-4o + hybrid RAG + LLM segmentation (closed-model reference) 84.12 84.96 84.54
Llama-3.3-70B SFT + self-consistency voting + Llama-70B verification (best open-source) 84.21 77.48 80.70
Llama-3.3-70B SFT + hybrid RAG, 0-shot 74.32 78.71 76.45
Llama-3.3-70B base + hybrid RAG, 0-shot 70.48 78.49 74.27
Llama-3-8B base + hybrid RAG, 0-shot 49.64 80.36 61.37
  • SFT plus voting plus verification brings the open-source 70B model from 74.3 to 80.7 F1, within 4 points of GPT-4o. Most of that gain is precision: the verification pass cuts hallucinated observations from 306 to 148.
  • Schema retrieval: hybrid BGE + BM25 reaches 99.4% recall@60. Dense BGE alone reaches 97.4% and BM25 alone 90.0% (results/outputs/retrieval_table.csv).

The ten test-set submissions are in results/submissions/.

Data Availability

The task data comes from the MEDIQA-SYNUR 2026 shared task organizers: the observation schema plus train, dev, and test transcripts. It is not redistributed here. To obtain it, register for the shared task through the organizers and place the files in data/raw/ as described in docs/setup.md. data/raw/ is gitignored.

The transcripts are synthetic nurse-patient dialogues. This project does not use any real EHR or other clinical data, and no PHI is involved.

What this repo does contain that is derived from task data. The run outputs under results/outputs/ are kept exactly as they were produced during the shared task:

  • per-transcript predictions, including the observation values extracted from transcripts;
  • the organizers’ gold observation labels for the train and dev transcripts. Each predictions.json embeds a gold field, and reference.jsonl holds the train gold.

The ten test-set submission files in results/submissions/ are kept as well. These were all tracked in the upstream repository and remain in this copy’s history. They were kept deliberately, as a record of the submitted system. The transcripts themselves are never committed. Anyone reusing these outputs should check the shared task’s data terms first.

How to Reproduce

# setup (Python 3.11)
conda env create -f environment.yml && conda activate synur
#   or: pip install -r requirements.txt
cp .env.example .env              # add OPENAI_API_KEY for GPT runs / GPT verification
# place the task data in data/raw/  (see docs/setup.md)

# list pipeline stages
python src/main.py --list

# re-score a committed run with the official scorer (no task data needed);
# reproduces GPT-4o-mini + BGE dense, train: P 82.75 / R 72.49 / F1 77.28
python src/main.py evaluate \
  -r ../results/outputs/Meta-Llama-3-8B-Instruct/train_BGE_top60_enhanced/reference.jsonl \
  -p ../results/outputs/gpt-4o-mini/train_BGE_top60_enhanced/run_20260202_234051/submission.jsonl

# full run (needs task data in data/raw/)
python src/main.py run --data dev --model gpt-4o-mini \
  --embedding-model BAAI/bge-base-en-v1.5 --hybrid --hybrid-alpha 0.6 --top-n 60 --enhanced-prompts

Stages run with src/ as the working directory, so paths passed to them are resolved from src/. The exact 70B SFT, voting, and verification commands are in the valkyrie_scripts/*.sbatch files.
